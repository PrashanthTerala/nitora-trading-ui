# Design system

Nitora Trading Academy should look and feel like a premium, professional fintech product
without losing what it is: a free, honest, no-sign-up school with a simulator on invented
markets. This document is the design system that gets it there. The exact values live in
code and are listed in [tokens.md](tokens.md), which is generated from it.

## Direction: "Terminal Luxury"

A dark, quiet, high-end trading terminal crossed with a well-typeset textbook.

- Deep navy-black surfaces with hairline borders.
- One confident accent colour for actions and active states.
- Green and red only where price direction actually matters.
- Generous whitespace in lessons; dense but orderly panels in the simulator.
- Serious, calm, expensive. Never neon-crypto-casino, never hype.

Dark is the default theme and the primary design target. Light must be just as good: every
token has a light value held to the same contrast bar.

## Tokens are the contract

Every colour, type size, shadow and motion value is a token in
[`src/styles/tokens.css`](../src/styles/tokens.css), exposed through Tailwind v4's `@theme`,
so components use utilities such as `bg-surface-1`, `text-ink-soft` and `border-line-strong`.
Components never contain a raw colour.

`npm run check` runs `tools/lint-tokens.mjs`, which fails the build when:

- a hex, `rgb()`, `hsl()`, `oklch()` or similar literal appears in `src/` outside the files
  that must hold concrete colours: the tokens, the colour maths, the SVG and canvas
  renderers, and 3D scenes;
- a Tailwind palette class such as `bg-red-500` or `text-white` is added. The ones that
  predate the tokens are recorded per file and may only go down;
- a colour pair falls below its contrast bar in either theme;
- a colour token is outside the sRGB gamut, where it would render differently from what its
  contrast was measured on;
- `docs/tokens.md` no longer matches `tokens.css` (`npm run tokens:doc` regenerates it).

The contrast rules themselves live in `src/lib/tokenPolicy.ts`. The lint and the `/__tokens`
review sheet both read them, so the sheet shows exactly what the build enforces.

## Colour

Authored in OKLCH, because its lightness is perceptual: two colours at the same L look
equally light, so a surface scale steps evenly and a chart palette stays balanced.

| Layer | Tokens | Rule |
|---|---|---|
| Surfaces | `bg`, `surface-1` (cards), `surface-2` (nested panels), `surface-3` (popovers), `overlay` (modal scrim) | Cool, low-chroma neutrals at hue 255. Light surfaces are near-white with a cool tint, never pure white over a large area. |
| Lines | `line-subtle`, `line`, `line-strong` | 1 px hairlines. On dark, borders are lighter than the surface, never darker. `line-strong` is for controls and reaches 3:1. |
| Ink | `ink`, `ink-soft`, `ink-muted`, `ink-inverse` | All three text tones reach 4.5:1, captions included. |
| Accent | `accent`, `accent-hover`, `accent-soft`, `accent-ring`, `on-accent` | One hue only: electric blue-violet at OKLCH hue 272. |
| Market | `up`, `down`, `neutral`, their `-soft` tints, `on-up`, `on-down` | Price direction, P&L and order sides **only**. The only saturated colours besides the accent. |
| Status | `warn`, `danger`, `info` and `-soft` tints | Never for price direction. `danger` is deliberately more magenta than `down`, so a warning is never read as a losing trade; the lint holds them apart. |
| Levels | `level-foundation` … `level-mastery` | Five muted hues for small identifiers — a dot, a ribbon, a cover tint. Never a large fill. |
| Chart | `chart-1` … `chart-6` | Indicator overlays. Colour-blind-safe hues and none of them green or red, so an overlay is never mistaken for price direction. `chart-6` is a neutral slate for envelopes and reference lines. |

`on-accent`, `on-up` and `on-down` are additions to the original brief. Today's buttons use
white labels, which in the dark theme measure 2.5:1 on the accent and 2.3:1 on Buy — well
under WCAG AA. Each strong fill therefore has its own label colour that clears 4.5:1.

`surface` and `panel` remain as aliases of `surface-1` and `surface-2`, so existing classes
keep working while components move over.

## Type

| Family | Token | Use |
|---|---|---|
| Inter | `--font-sans` | Body and interface |
| Geist | `--font-display` | H1/H2 and hero numbers |
| JetBrains Mono | `--font-mono` | Prices, tickers, R-multiples, code |

All three are self-hosted variable fonts in `public/fonts/`, generated by
`tools/copy-fonts.mjs` from the `@fontsource-variable` packages (SIL Open Font Licence). No
request leaves for Google or anyone else. Only the Latin and Latin Extended subsets are kept:
they cover every character the site uses, including the minus sign in prices. File names
carry the package version, so the server caches them as immutable. The body face is
preloaded.

Every number that can change width uses `tabular-nums`.

The scale: `display-xl`, `display`, `h1`, `h2`, `h3`, `body-lg`, `body`, `prose`, `body-sm`,
`caption`, `mono-lg`, `mono`, `mono-sm`. Display and headings are fluid (`clamp()`) with a
line-height of 1.05 for display and 1.2 for headings, tracked tight (`-0.02em`). Lesson prose
is 16 px on mobile and 17 px on desktop at a 1.7 line-height, capped at a 68ch measure.
All-caps labels are 11–12 px, tracked wide (`0.08em`).

## Space, radius, elevation

- A 4 px spacing base, which is Tailwind's default. Marketing sections breathe at 96–128 px on
  desktop and 64 px on mobile (`--spacing-section`).
- Radii are named by what they round, not by size, so Tailwind's own `rounded-lg` and friends
  keep their meaning on pages not yet rebuilt: `rounded-control` and `rounded-panel` 10 px,
  `rounded-card` 14, `rounded-dialog` 20, `rounded-feature` 28. Chips are fully round.
- Layout heights are tokens too: `--spacing-header` (60 px) and `--spacing-tabbar` (64 px), so
  anything that sits under the header or above the mobile tab bar (`top-header`, `pb-tabbar`,
  the simulator's full-height workspace) moves with them.
- Elevation on dark comes from border lightness plus a faint inner top highlight, not from
  drop shadows — a shadow on a near-black page reads as a smudge. Light mode uses soft layered
  shadows. Both are the `--shadow-1` … `--shadow-4` tokens.
- Glass (`backdrop-filter: blur(12px)` over a 70–80% surface) is allowed only on the sticky
  header, the command palette, modals and the mobile order ticket. Nowhere else: blur is
  expensive.

## Motion

| Duration | | Easing | |
|---|---|---|---|
| `fast` 120 ms | hover, press | `standard` `cubic-bezier(.2,0,0,1)` | most movement |
| `base` 200 ms | most transitions, route change | `emphasized` `cubic-bezier(.3,0,0,1)` | deliberate entrances |
| `slow` 320 ms | panels, sheets | `exit` `cubic-bezier(.4,0,1,1)` | things leaving |
| `deliberate` 600 ms | number flashes, emphasis | | |

- Animate only `transform` and `opacity`, never width, height or position.
- Under `prefers-reduced-motion: reduce` every duration token becomes 0 ms, so no component has
  to remember to check.
- Route changes fade and rise 8 px over 200 ms, on enter only: there is no exit phase, so a
  click never waits for the old page to leave. Card grids stagger 40 ms (at most eight items).
- `motion/react` runs under `LazyMotion` (its features load after first paint) and
  `MotionConfig reducedMotion="user"`, which turns transform animations off for readers who
  ask for less motion. Hand-driven movement (the module cover's parallax, count-ups) checks
  the preference itself.
- Planned: changing numbers tween with a spring and flash their direction tint for 600 ms.

## Accessibility bar

- Every interactive element is keyboard-reachable, with a visible focus ring (`accent-ring`,
  3:1 against surfaces).
- 4.5:1 for text and 3:1 for large text, control boundaries and meaningful graphics, in both
  themes — enforced by the lint rather than promised. Decorative hairlines (`line-subtle`,
  `line`, `grid`) are exempt, per WCAG 1.4.11; anything a user needs in order to operate a
  control uses `line-strong`.
- All motion respects reduced-motion preferences.
- Figures keep a text alternative.
- Layouts work at 360, 768, 1024, 1440 and 1920 px, with no horizontal page scroll.

## Performance budget

- Initial JavaScript for the home route at most 250 kB gzipped.
- Any 3D scene is a separate lazy chunk. It loads only when in view, only without reduced
  motion, and only when `navigator.deviceMemory` (if reported) is at least 4. A static WebP
  poster renders first and remains when WebGL is unavailable.
- Lighthouse Performance of at least 90 and Accessibility of at least 95 on Home, Learn, a
  lesson and the simulator, on desktop.

## Imagery

- `lucide-react` icons at a 1.5 px stroke.
- Each module gets a 3D-rendered abstract cover (a glass block for markets, translucent
  candles for patterns, a staircase for market structure, a shield for risk), rendered to WebP
  at build time in dark and light variants, plus a 64 px SVG glyph. These replace the emoji
  module icons.
- The home hero, section dividers and empty states share that visual language.

## Tone

Truthful to what the site is: free, no sign-up, synthetic markets, educational. No fake
testimonials, no fabricated statistics, no "guaranteed returns" imagery.

## Where things stand

The overhaul runs in phases, each ending with `npm run check` green, a production build, and
screenshots at 390 and 1440 px in both themes under `docs/screenshots/phase-N/`.

| Phase | Scope | Status |
|---|---|---|
| 0 | Audit, tokens, self-hosted fonts, motion tokens, token lint, `/__tokens` sheet | **done** |
| 1 | Shell, command palette, toasts, Home, Learn, Module; tracks refactor | **done** |
| 2 | Lesson read mode, MDX component restyle, component registry | **done** |
| 3 | Presentation mode (auto-generated slide decks) | next |
| 4 | 3D hero and module artwork | |
| 5 | Simulator, Trainer, Journal, Glossary, Guide, 404 | |

### Decisions made in Phase 0

- **Neutrals stay close to today's lightness.** Dark `bg` is L 0.15 against the brief's
  "~0.13", so that Phase 0 changes colour, not character. It can be deepened in one line once
  the rebuilt components are on screen to judge against.
- **The radius scale is written down, not yet applied.** Defining it under Tailwind's own
  names (`rounded-lg` 8 → 14 px) would restyle every card and button at once. It went live in
  Phase 1 under semantic names instead (see above).
- **The type scale, display face, shadows and label colours are defined but not yet used** by
  existing components, for the same reason. The `/__tokens` sheet shows them in use.
- **Labels on strong fills** (`on-accent`, `on-up`, `on-down`) were added to fix today's
  button contrast.
- **The token lint goes beyond the brief:** it also checks contrast, gamut, palette classes
  and whether the generated docs are current.
- **The simulator chart keeps its own colours until Phase 5.** It draws on a canvas, which
  cannot read CSS variables; `src/lib/tokens.ts` already resolves a token to a concrete
  colour for it.
- **Screenshots use `playwright-core` with the installed Edge**, not a full Playwright install,
  so no browser download is needed. `tools/screenshots.mjs` also diffs two sets pixel by
  pixel.

### Decisions made in Phase 1

- **Components live in `src/components/ui/`** (Button, Card, Chip, Ring, Segmented, Tabs,
  Tooltip, Dialog, Sheet, Kbd, Skeleton, Toast, plus Switch, Sparkline and CountUp), with
  variants written as literal class tables so Tailwind can see them. The old `.btn-*`,
  `.input` and `.chip` classes remain as thin aliases in the components layer, where a
  utility on the same element now overrides them, as intended; before, they silently won.
- **Placeholder covers** are drawn from the module's level colour with a candle silhouette
  seeded from the module id, so each module keeps its own shape until Phase 4 renders art.
- **The home page shows only real data.** The ticker and the simulator preview are computed by
  the engine at the simulator's default seed and opening clock (tested to match), after first
  paint. The lesson showcase is read from the engulfing lesson at build time by a Vite
  plugin, so it cannot drift from the lesson. The journal preview reads the reader's own
  closed trades, or says it is empty.
- **The hero poster is inline SVG, not WebP,** until Phase 4 has a 3D scene to render one from.
  It follows the theme and costs no request.
- **The command palette matches whole words**, not cmdk's default fuzzy score, which let
  "engulf" match "Economic Calendar".
- **Track tabs appear only with a second track.** `/learn/t/:trackId` exists now so a second
  track is a content change.

### Decisions made in Phase 2

- **Lessons load on demand.** The lesson page and everything it carries (the MDX registry,
  figures, calculators, the glossary for term cards) is a lazy route, and the figure lightbox
  loads on first use. Home's initial JavaScript fell from 198.5 to 155.0 kB gzipped.
- **Heading anchors are made at build time** by a small rehype step (`src/lib/rehypeHeadingIds.ts`)
  that numbers repeats, because one lesson repeats "Worked example" three times and lesson
  prose is not edited to suit the page.
- **Only registered components.** `src/components/mdx/names.ts` lists every component by group;
  the registry is type-checked against it and the content linter reads it, so an unknown or
  planned component fails `npm run check`, not the page.
- **Two unlayered global rules were fixed.** The default border colour (`* { border-color }`)
  and the lesson prose rules sat outside Tailwind's layers, so they silently beat utilities:
  no `border-accent` or `border-up` had ever shown. Both now live in layers; a few borders
  elsewhere (active chips, inputs) now show the colour their classes always asked for.
- **Prose styles skip components.** Prose element rules are wrapped in `:where()` and exclude
  anything inside `.not-prose`, except markdown a component wraps (marked `.md`: callout bodies,
  takeaways, comparisons). Before, prose list and link styles leaked into the quiz and buttons.
- **Figures redraw narrower on phones** (420 units instead of 640) so candles scale up rather
  than shrink, and wider in the lightbox (960 × 400) so it adds detail, not just size.
- **Callouts use status colours only** (accent, info, warn, danger, neutral), never up/down.
- **Per-route metadata is set in place** on the tags index.html already has, so nothing is
  duplicated and leaving a page restores the defaults. Crawlers that run no JavaScript see only
  the defaults; per-page previews for them would need prerendering (not done).
- **The sitemap needs the site's address.** `SITE_URL` at build time (a Docker build argument)
  writes `sitemap.xml`; without it only `robots.txt` is written, since sitemaps need absolute URLs.
- **Presentation mode is Phase 3.** The read/present toggle and the `p` shortcut arrive with it.

### Known issues found in the audit, to fix as the components are rebuilt

- Button labels failed contrast in the dark theme. Fixed for buttons in Phase 1; the order
  ticket's Buy and Sell follow in Phase 5.
- Input borders used the decorative `line`; fixed in Phase 1 (`line-strong`).
- Callouts used Tailwind palette classes (28 of the 30 remaining). Fixed in Phase 2; one
  remains, in the order ticket (Phase 5).
